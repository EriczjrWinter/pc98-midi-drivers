> * `build/_mako_lab/midi_fm/` —— 21 首 MIDI，program change 已重映射到该 bank 的槽号

> ### 本文档下面几处已被证伪，正文保留作历史记录：
>
> 1. **§三 步骤 3 的「256 字节块」不存在于 `AMUS.DAT`** —— 那是 Windows 版 `system3.exe`
>    的 MDA 资源结构。PC-98 版的音色是每曲块内 **43 字节/条**，
>    条数 = `(chptr[0] - w0) / 43`（21 首实测 1–10 条，共 121 条 → 26 种）。
> 2. **§五 已知坑 5「0x188 还是 0x088」不完整** —— FM 通道 0-2 用 `base+0/+2`，
>    **FM 通道 3-5 用 `base+4/+6`**（PC-98 上是 0x18C/0x18E）。
>    只 hook 0x188/0x18A 会漏掉三条 FM 轨。基址默认 0x0088，`-p1` 才是 0x188。
> 3. **§四 验收判据 ① 要按通道拆开** —— FM 版只有 6 条 FM 轨会在端口上产生 note-on，
>    ch3-5 是 SSG（走音高寄存器），拿总数对 MIDI 会正好少三条轨。
> 4. **步骤 2 不需要跑** —— 静态解析 121 条记录即可，差异集中在 alg/fb/AR/D1R/D2R/DR/RR。
>
> 另外：导出的寄存器流反解回去应当等于原始 43 字节记录——这条比"两次运行逐字节相同"
> 有意义得多。

## 二、要回答的三个问题

1. **音色从哪来**：`AMUS.DAT` 里的 256 字节块装的是 FM 寄存器参数，还是音色号（再由驱动查表）？
2. **怎么转**：驱动在 note-on 时写了哪些寄存器（`0x188/0x18A` 等），值的顺序与含义。
3. **包络谁算**：AR/D1R/D2R/RR 是驱动写死、查表、还是芯片默认值。

## 三、方法（核心：端口日志，不是 code hook）

> 风雅那轮的血泪教训：**播放期不要用 code hook**（会改 flags，制造"驱动怪癖"）。
> 这里用**端口 I/O 日志**——它不改变指令语义，等价于风雅的板卡日志。

### 步骤 0：装载
在 Unicorn（16 位，PC-98 环境）里装载 `MAKO_98.COM`，准备好 `AMUS.DAT` 与 DOS INT 21 桩。
可复用风雅的仿真骨架：`D:\gf\pc98-midi-drivers\build\_fmd_play3.py`、`_fmd_export.py`。

### 步骤 1：抓端口写（第一份数据）
记录**所有**对 `0x188`（地址口）、`0x18A`（数据口）的 `out`，附带 tick：
```
{tick, port, value}
```
同时记录 `0x18C` 之类状态口读，以及 INT 中断号调用。

**判据**：能抓到成组的 `写地址 + 写数据`，且 tick 0 之后有规律出现 → 驱动在工作。

### 步骤 2：确认"音色表存不存在"（关键实验）
选**两个不同音色**的 note-on（最好来自不同曲子/不同通道），对比那一刻的寄存器写：

| 观察 | 结论 |
|---|---|
| 两组寄存器值**完全相同** | 没有音色表，全硬编码/默认 → 问题 3 答案 = 芯片默认 |
| 部分不同（尤其算法/倍率/AR/D1R/RR） | 有表，且按音色号索引 → 进入步骤 3 |

### 步骤 3：定位参数来源
- 若**同一首曲子里音色固定**：说明音色是曲级的（与 AMUS.md 的"按曲索引块"一致）；
- 在这首曲子的 256 字节块里找**与寄存器值相同的字节序列**；
  找到 → 块即参数表；找不到 → 驱动内还有另一张表，转步骤 4。

### 步骤 4：静态定位（仅在步骤 3 失败时）
反汇编 `MAKO_98.COM`：
```
找 note-on 处理里的索引读：mov al,[bx+si] / mov al,[si+参数] 
si 的基数 = 表地址；步长 = 每组字节数
校验：表里第 N 组的字节 == 步骤 1 抓到的寄存器值
```

### 步骤 5：与 MIDI 版对齐（交叉验证）
```
同一首曲子：
  MIDI 版（AMUS.md 已解）→ program change 号序列
  FM 版（本实验）        → 音色切换时刻 + 寄存器组
两者在【时间轴】上应一一对应。
```
对不上 → 说明两版对同一份数据的解释不同，记录差异点（这本身就是结论）。

## 四、验收判据

```
① 能完整导出一首曲子的 FM 寄存器流，note-on 数量与 MIDI 版音数一致（±5%）
② 至少两首曲子，寄存器流可复现（两次运行逐字节相同）
③ 明确回答：音色参数来自 数据块 / 驱动表 / 硬件默认（三选一，附证据）
```

## 五、已知坑（继承自风雅）

1. **不要用 code hook 观测**——会改 flags，制造假象；用端口日志；
2. **YM2608 初始化序列很长**（`0x181` 等），先过滤掉，只看 note-on 附近的写；
3. **SSG 部分**（AY 兼容）包络是 16 种固定波形，驱动只写编号——别当 FM 参数解析；
4. **ADPCM 通道**（YM2608 的 0x101/0x100）若被用到，单独记；
5. 端口基址可能由 DIP/命令行改（0x188 或 0x088），**先扫一遍**确认；
6. 产物按 `docs/OUTPUT-LAYOUT.md` 放，**不要写进 D:\music**。

## 七、如果一开始就跑不起来

按这个顺序排查（都是风雅踩过的）：
```
1. 驱动装上了吗？（INT 向量是否被改）
2. 数据怎么交给驱动的？（DS:DX？文件名？AH 号？）看 MAKO 里的 INT 21/INT 向量
3. 有没有等某个中断/时钟？PC-98 的 Timer B 或 VBLANK（0x0A0B/0x0A0D）
4. 先让它在 HOOT 里能出声，再用同一份数据在 Unicorn 里复现
```
