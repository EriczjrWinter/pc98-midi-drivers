# 最小海森堡模型：为什么这个目录存在

## 一句话

**我们花了六天，最后发现"驱动行为诡异"其实是"我们的探头改变了它"。**

这个目录里的 `demo.py` 把那次事故压缩成 60 行、可运行的最小模型。

## 背景（真实事故）

逆向风雅（FUGA）的 FMD 驱动时，我们用 Unicorn 跑 16 位仿真，
为了看驱动内部状态，在播放路径上挂了一段 `UC_HOOK_CODE`。

结果得到了一整套"发现"：

```
查表分派「不命中」
F8 循环计数「永远已完成」
循环锚点「每次只前进 4 字节」
```

三条看起来都像驱动本身的怪癖，于是我们顺着它们改表、补丁、调参——
**花了三天，越改越远**。

直到把播放期的 hook **全部拆掉**：

```
分派正常、计数正常、锚点步长与真机一致（+4 … +0xC4）
```

再和 HOOT（参考实现）的内存对照，三条"怪癖"全部消失。

**结论：不是驱动怪，是探头把 `cmp` 的 CF 弄丢了。**

## 为什么叫"海森堡"

量子力学的不确定性原理说：测量本身有下界，绕不过去。

**我们这个不是。我们这个能绕过去**——换成板卡日志、外部读内存，零扰动，一切正常。

所以更贴切的比喻是电子学里的"探头负载"：

> 拿万用表量高阻节点，表的内阻会把电压拉下来。
> 读数是准的，但**被测对象已经不是原来那个了**。

## demo.py 演示什么

```
同一个程序、同一份输入（val=3，与 3 比较），只改"观测方式"：

  无探头                → 6
  探头插在 cmp 和 je 之间 → 3    ← 用了陈旧的标志位快照
  探头插在 cmp 之前      → 6    ← 链还没建立，打断无害
```

第三行是关键：**同一个探头，插错位置就造出不同的世界。**

## 怎么用这个模型

不要把它当理论。当你在调试里遇到"**这个驱动行为好怪**"的时候，先问三句：

1. 我现在的观测方式，会不会改变被测对象？
2. 如果换一种观测方式（日志 / 快照 / 外部读），结论还成立吗？
3. 两次观测不一致时，我凭什么相信其中一次？

**两次观测量出两个世界，就该先怀疑探头，而不是先怀疑驱动。**
