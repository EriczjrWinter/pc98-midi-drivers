# 逆向手册：PC-98 MIDI 驱动（写给接手的人）

> 这份文档不是格式说明（那些在各驱动 `docs/` 里），而是**怎么干活**：
> 怎么观测、怎么怀疑、怎么验证、怎么记录。风雅那六天就是踩在这上面
> ——其中**前三天全耗在"探头污染"上**，后三天才是在解驱动。这个比例本身就是教训。

## 0. 先记住一句话

**当读数让你觉得"这个驱动好怪"时，先怀疑读数。**

风雅三次"驱动怪癖"（查表不命中 / F8 计数永远完成 / 锚点步长异常）全部是探头污染造成的；
拆掉 code hook 之后三件事一起消失，和 HOOT 对得上。

## 1. 观测纪律（最高优先级）

### 1.1 绝对不要做的事

- ❌ 在播放路径上挂**全范围 `UC_HOOK_CODE`**；
- ❌ 在 hook 回调里读/写寄存器或标志位；
- ❌ 拿"文件镜像"当"执行镜像"反汇编（驱动会自改写）。

风雅事故的机制：hook 回调让 `cmp` 的 CF 丢了 → 查表永远不命中 → 整张命令表作废
→ 驱动的"丢记录""鼓不响""通道错"全是这一个原因的连锁反应。
可运行的最小模型见 `lessons/heisenberg/demo.py`。

### 1.2 可以放心用的观测

| 方式 | 扰动 | 用法 |
|---|---|---|
| 内存写 watchpoint（只盯某个字段） | 零 | `hook_add(UC_HOOK_MEM_WRITE, cb, None, addr, addr+1)` |
| 板卡日志（0xE0D0/0xE0D2 记录） | 零 | 事后分析，不打断执行 |
| 事后 dump 内存 | 零 | 比对两次快照 |
| 外部参照（HOOT 的模拟内存） | 零 | 逐字节比对，最强的真值来源 |

### 1.3 反汇编前必做

1. **确认指令边界**：从 0x1010:0x08C1 读到的 IP 可能落在半条指令中间；
2. **确认基址**：`linear = (CS << 4) + offset`；文件偏移还要加 MZ 头长度；
3. **确认镜像**：以"执行当刻"的活内存为准，静态镜像可能被改写、也可能根本对不上；
4. **两次观测不一致时**：先查探头，再查驱动。

### 1.4 怎么找到某个记录的 handler（通用手法）

不要一上来就全量反汇编。用**内存写 watchpoint** 顺着数据找到代码：

```
1. 先确定哪个字段会随该记录变化（如 cur = [bx+4]）
2. 挂 watchpoint：hook_add(UC_HOOK_MEM_WRITE, cb, None, addr, addr+1)
3. 命中时读活内存：把 CS:IP 附近 32 字节打出来（这是"执行当刻"的字节）
4. 从命中点往回找分派链（cmp al, 0xFxh 那一串），就找到该记录的分支
```

风雅的 `F9`/`F8`/`FD`/`FC` 四个 handler 全是用这个方法定位的；
反过来，"先静态反汇编再猜哪段是 handler"在会自改写的驱动上经常对不上。

## 2. 卡住时的排查顺序

1. **裸环境复现**——不挂任何 hook，用日志/内存观察，看现象还在不在；
2. **换观测方式**——同一结论换一种探头还能复现吗？
3. **外部真值对照**——HOOT 的内存/行为是裁判，不要自己跟自己比；
4. **最后才怀疑驱动**——驱动是死的，只有指令在跑；
5. **同一个问题改了三轮还在长新特例 → 停手，回去读代码**。

反面教材：风雅花了三天顺着"驱动怪癖"改表、打补丁、调参数，越改越远。
同样地，曲尾那 5 首卡了两天，方向一直是"再调一下判据"；
最后解决它的是**读 `0x0CE7` 那条 handler**（锚点同步），不是第十次调参。

## 3. 机制优先于拟合

**能读代码就读代码，别用常数拟合。**

实例（2026-11-27，曲尾截断）：

- 拟合法：发现差额是 `384 = 4×96`、`1548 ≈ 16×96`，于是猜"FD/FC 屏障对齐到 96 tick 网格"。
  这能解释这 4 首，但换个曲子就未必成立；
- 机制法：把 `FD/FC` 的处理器读出来（A 代 `0xB22` / B 代 `0x0CE7`），
  发现是**锚点式同步**——跳转目标来自锚点 `[bx+2]` 处的 FC 指针，不是当前记录；
- 结果：五首一次全对，且是整数级对齐（`runtime = static + 1`）。

**判据**：拟合出来的规则只能解释"见过的样本"；机制推出的规则能预测"没见过的样本"。
当一个修法需要越来越多特例时，说明方向错了，回去读代码。

## 3A. "循环"不是层号，是状态周期

风雅收尾的最后一课（FMD5248，2026-11-27）。当时 10 首卡在"周期取外层还是内层"：
按 `depth=1` 得 17664，按 `depth=2` 得 8832，两种都能自圆其说。

正确做法是**完全不看层号**：

```
V(t) = 全部活跃轨的 (seg, cur, anchor, depth, en) 拼接
找最小 P ≥ 96、最早 A，使
    V(A..A+P) == V(A+P..A+2P) == V(A+2P..A+3P)
C = A + P
```

- **为什么层号不行**：无限循环一旦进入就出不来，外层状态永远不会真正复现；
  按层挑会选到"假外层"（DORA_M 的 17664 = 两个 8832）；
- **为什么周期行**：它只问"状态什么时候整体复现"，不关心发生在哪一层；
- 结果：TITLE `A=195 P=3264 C=3459`（SHA 不变）、DORA_M `A=784 P=8832 C=9616`，
  6 首也各自得到自己的真实周期（旧动态版的"更长"是自相似相位错，不是真值）。

**判据**：如果"一轮"需要靠层号或数据结构来定义，那多半定义错了——
用**行为序列的周期性**定义，再用运行时的状态重复做交叉验证。

## 4. 数据约定 ≠ 驱动字面

驱动的代码是死的，但**数据是按约定写的**。两者冲突时，以"能解释全部曲子的那一侧"为准，
并把这个冲突写进文档。

实例：

- `F8` 的次数：驱动只把 **0** 当无限（`or dh,dh; je`），但数据里 **0xFF 也当无限哨兵**用——
  按字面 255 次处理会得到 380 小时级别的荒谬时长；
- `F8` 的 0xFE：数据里用于"停轨"，不要和"循环结束"混淆；
- 结束时没有 `$FF/$32` 停止命令，数据是自然走完的——别等一个不存在的信号。

## 5. 风雅（FMD）记录与循环的具体坑

格式：4 字节 `[cmd][dur][p1][p2]`；`dur` = 到下一条记录的 tick 数。

| 坑 | 说明 |
|---|---|
| **零时长记录同拍消费** | `dur=0` 的记录在同一拍内连续处理，直到遇到 `dur≠0` 才提交 `cur`；所以运行时 `cur` 与 `F9` 位置会差好几条记录 |
| **F8 的次数在第 2 字节** | `mov dh,ah`；不是 p1 |
| **F8 回跳落点 = F9 地址 + 4** | 驱动先 `bp=target` 再 `add bp,4` |
| **F9 最多 5 层** | 深度 5 时**不压栈**；后续 F8 仍会弹栈 → 深度会错位 |
| **FD/FC 是锚点同步** | 目标 = 锚点处 FC 记录的 `[+2] & 0xFFFC`（最多 10 层，0 退回锚点）；然后从锚点往后扫过 `<0xFC` 的记录、跳过一个 FD；目标记录若是 FE 就停轨 |
| **anchor 初值** | 来自轨道表 `+0x02`，不是 `cur`、不是 0 |
| **F8 只在回跳分支恢复 anchor** | 弹栈分支不恢复，别补对称 |
| **A 代 F7 = 无操作** | 分派链没有 F7 分支 |
| **A 代 F6** | `si = bp + 0x2A` 后继续，不改流向 |
| **`+1` tick 偏移** | 驱动第一拍在 tick 1 处理首记录；静态从 0 起算，比较时统一 `runtime = static + 1` |
| **`0x80–0xEF` 计时** | 除 `E6`/`E7`/`0x98` 外都按 `dur` 计时；`≥0xF0` 一律清零 |
| **轨道表基址** | A 代 `CS:0xE64`，B 代 `CS:0xEBC`；但**单个 build 可能偏移**，用 `find_track_table` + `fix_table_base` 校验 |

## 6. 验证方法（比"听起来对"可靠）

> **总纲**：任何 `|runtime − static| > 1` 的偏差都是**语义错**，不是舍入。
> 差 1 是"驱动第一拍在 tick 1 处理首记录"，是常数；差 2 以上就说明模型缺东西。

1. **逐轨 `en→0` 时间戳**：运行时记录每条轨停轨的 tick，和静态逐轨总长比；
2. **整数级对齐**：`runtime = static + 1` 全曲成立才算语义对；
3. **交叉验证**：358 首回归，任何一首偏差都说明语义缺东西；
4. **结构校验**：导出 MIDI 对 HOOT 的音高/时序，斜率 1.000±0.02 才算过；
5. **旧产物不是基准**：旧 SHA 只能做回归参照，旧文件本身可能就是错截断。

## 7. 交付纪律

- **不伪造事件**：数据里有、驱动不发，就标 blocked，不要按参考 MIDI 抄时间点补；
- **未验证的产物不引用**：补丁导出的文件标 `unverified`；
- **FM 一律 PASS**（本仓库政策）；
- **文档要写证据链**：地址、字节、命令、判据。只写结论的文档，下个人没法判断适用条件。

## 8. 协作与上下文

- **一个驱动一个会话**；上下文过半就写交接、换新会话；
- 交接要写"**为什么**"，不只是"做了什么"——否则经验无法继承；
- **战略层**给判断和方案（保留压缩后的经验），**执行层**跑长任务和总结；
- 决策必须能指回现场证据；执行层的总结要附原始数据（地址/字节/命令）；
- 定期换人看同一个问题——新人没有沉没成本，更容易发现系统性偏差。
