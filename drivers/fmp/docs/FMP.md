# FMP2 / FMP3 —— 戯画「音痴君」v3.04

PC-98 上由 **TGL / 戯画 / 夢幻** 三家共用的 MIDI 驱动，数据扩展名按音源分：
`.MGS`(GS)、`.MG2`(SC-88)、`.MD`/`.MMT`(MT-32/SC-55)、`.MF2`/`.MFM`(FM)。
本仓库只处理 MIDI 那几套，FM 按政策 PASS。

## 命名关系

```
tglfmp.com / tglfmp2.com   ← HOOT 的壳（127 / 90 字节），按 TGL 命名
FMP2.COM / FMP3.COM        ← 真身驱动，自报「ＦＭ＆ＭＩＤＩ音源バスター 音痴君。version 3.04月 (C)戯画」

> **例外**：TGL 的 `EDGE` / `SWORD DANCER 増刊号'93` 两个包里的 `FMP2.COM` 是
> **FFMP ver1**（`0x102` 有 `FFMP ver1` 签名，横幅 `ＦＭＰ ver.2.1` / `ver.2.2b`），
> 不是音痴君——INT D2 入口、AL 分派表、**时钟中断（INT 08h 而不是 INT 14h）**都不一样。
> 已解，见 `drivers/fmp/docs/TGL-FFMP-HANDOFF.md`。
```

壳的流程（`tglfmp2.com` 反汇编）：

```asm
mov dx,0x17f / xor bx,9 / mov cx,0x8fff / mov ah,0x3f / int 0x21   ; 读补丁文件
mov bx,cs / mov cx,0x17f / mov dx,ax / mov al,0x11 / int 0xd2      ; AL=11 灌 MIDI/SysEx
mov ax,0x257f / mov dx,0x132 / int 0x21                            ; 挂 INT 7F
int 0x18
; INT 7F: in al,0x7e0
;   0 → AL=0(int D2) → in al,0x7e4 → AH=值 → AL=8(int D2) → 读歌 → AL=1(int D2) 播放
;   2 → 停止
```

## 启动

```
FMP3.COM -m
```

不带 `-m` 只打横幅就退出；带 `-m` 打印「常駐しました」并 TSR，挂 **INT 0xD2**（API）
和 **INT 0x14**（音乐节拍）。

## API（INT 0xD2）

入口在 `1000:1893`，按 AL 查表（表基址 `cs:0x2DA`，AL 0–0x1A）：

| AL | 行为 |
|---|---|
| `0` | 复位（清 0x23 个通道槽） |
| `1` | **播放**：`ES:BX`/`CX` 指向歌曲，头 4 字节为格式标识，随后 11+20 个 word 的表 |
| `8` | 设模式：`AH=模式值`（GS=2），存 `[0x2046]` |
| `0x11` | 灌 MIDI/SysEx 数据（不是装歌） |

播放后内部状态：`[0x1E5A]`=1 播放中，`[0x3373]`=轨指针，`[0x29F0]`=音乐 tick 使能。

## 节拍与计时

INT 14h 处理函数读 OPNA 状态口 **`0x188`**，取 Timer B 位（bit1）作为 tick 标志，
再写 `0x27=0x3F` 重新武装。所以仿真时 `0x188` 要返回 `0x02`，并每次调用 INT 14h。

Timer B 的周期在播放中被改写（`0x26`）。用 VG00 对参考 MIDI 拟合：

```
tick_ms = (256 − TimerB) × 0.2991
```

每首曲子的 Timer B 不同（VG00=208 → 14.36ms；SH01=230 → 7.78ms），和 MDRV98/MSDRV4 同理。

## 导出结果（`build/hootcap/fmp/<游戏名>/`）

`build/fmp_batch.py`：装驱动 → `AL=8 AH=2` → `AL=1` 播放 → 循环 INT 14h → 抓 `0xE0D0`，
按 Timer B 建时间轴写 SMF。曲名取自 HOOT `<titlelist>`。

19 个音痴君包全部跑通，**522 个 MIDI、405 首不重复**：

|---|---|---|

| TGL | ファーランドストーリー 1–7（18/14/21/21/20/25/29）、あっぱれ伝（30）、機装神伝ゲンカイザー（21）、ソードダンサー 凶刃の女神（24×2） | 264 |
| 夢幻 | Horny Sweeper（15）、Horny Sweeper2（19） | 34 |

另有两个 **FFMP ver1** 包（EDGE 25、SWORD DANCER 増刊号'93 13×2 = 51），见下节；
合计 **21 包 573 个 MIDI（443 首）**。

> 旧文档写的"574 个"是**把这个 522 加上当时两个 FFMP 包的 52 个空文件**得来的
> （26+26），不是 19 包的真实数。现在两个 FFMP 包出的是真文件，所以总数是 522+51=573。

变体后缀：`.MGS`→`_GS`、`.MG2`→`_SC88`、`.MMT`→`_MT32`、`.MD`→`_SC55`。

**BGM 导出两遍循环，OP/ED 一遍**：驱动在循环的曲子会一直播，我们按循环周期截两遍；
自然结束的（片头/结局这类）保持一遍。这样戏画那批的时长就和 Win 版对上了
（放たれた矢 184.8s vs Win 186.1s、慟哭 223.5s vs 223.3s）。

## 循环 / 结束的处理（关键）

一开始按「开头 240 音再现」找循环，结果把曲中的**内部重复**当成了整曲循环，
`真実の勇気` 被截成 1:13（实际 1:55）。现在：

1. 若捕获**到达上限**（曲子确实在循环）→ 用 `find_song_end` 截；
2. 若驱动**自然停止输出**（曲子有结尾）→ 按全长导出，不做截断；
3. 空闲阈值 4000 → 25000 tick（有的曲子中间有长休止）。

## 与参考 MIDI 的校验

- **VG00**：我们 127.3s / 4223 音；参考 `VG00_GS.MID` 125.7s / 4235 音 → 内容对齐 99.7%。
- **HB01 True Courage**：我们 114.9s / 4293 音；Win 版 110.8s / 4087 音 → 一致（单遍对单遍）。
- **SH00**：我们 71.2s / 2226 音；Win 版 69.0s / 2244 音 → 一致。
- **SH01 / Harlem Blade 其余曲**：Win 版是「单遍 + 一次循环」（时长、音符约 2× 于单遍），
  不是额外编曲——原因见下节。
- VGZ 是 FM 版录音，不作 MIDI 的时长基准。

### 戯画 Win 版的真相

早期我们把 Win 版时长 2× 当成「戯画改过 MIDI」，实际是 **Win 版按驱动行为循环了一遍**：

1. FMP 驱动循环时**不回曲首**，而是跳到数据里的另一个位置（见下节）；
2. 所以 Win 版 = 单遍 + 一次循环，第二遍不是第一遍的复读；
3. OP/ED 这类本来一遍就结束的曲子，Win 版也只有一遍；
4. 「Win 更长」不是我们短，而是它多放了一次循环。

我们的导出现在与之一致：**循环曲两遍、OP/ED 一遍**。剩下的时长差（±2~4%）来自 tick 模型的
近似，属于可忽视误差，不据此回改 PC-98 侧的导出。

## 循环回跳点不在曲首

FMP 驱动循环时**不回到曲首**，而是跳到数据里的另一个位置。以 `ソードダンサー 凶刃の女神`
的「オルトウの森」为例：

- 单遍版 68.8s / 1888 音；
- 循环一次版 137.9s / 3833 音；
- 第 1 遍 1888 音与单遍版**逐音一致**；
- 第 2 遍 1945 音与单遍版开头的音序只重合 **93/1888**——回跳点在曲中，不是曲首。

所以两版的**结尾完全不一样**，这是驱动自身的循环逻辑（Win 版因此只放一遍）。
我们的循环导出是驱动实际输出的复现：第二遍从真正的回跳点继续，**不要**人为把它复制成第一遍。

## SysEx 越界字节



驱动会发 `F0 41 10 42 12 40 01 3F 00 80 F7` 这类 GS DT1，数据字节 **0x80 超过 7 位**，
严格解析器会拒收（574 个文件里 76 个中招）。导出时把 SysEx 数据字节压到 `0x7F`，
终端的 `F7` 保留；已生成的文件也原地修过一遍。

## FFMP ver1（EDGE / SWORD DANCER 増刊号'93）

这两个包的 `FMP2.COM` 是另一支驱动（签名 `FFMP ver1`，横幅 `ＦＭＰ ver.2.1` / `ver.2.2b`），
**时钟走 INT 08h + 8253 ch0**，不是音痴君的 INT 14h + OPNA Timer B：

```
tick_ms = 2 * cs:[0x6EF] * cs:[0x6F3] / 2457.6     ; 默认 13.74 ms，0x82 命令会改写两者
```

- 壳只调 `AL=0 → AL=8 AH=2 → AL=1`；`AL=8` 的 AH **必须 2** 才往 `0xE0D0` 发音符；
- sdz93 的 ver.2.2b 还要命令行 `M`（否则 18 轨全关，装得上但 0 音）；
- `AL=0x11` 非法（表只到 `0x0E`），`MIDIEFE.MD` 是壳喂它的音色数据，不是歌；
- 导出器 `build/tgl_ffmp.py`，产出 `build/hootcap/fmp/EDGE/`（25 首）与
  `build/hootcap/fmp/SWORD DANCER 増刊号'93/`（13 首 × GS/MT-32）；
- 技术细节、地址表、循环判定：`drivers/fmp/docs/TGL-FFMP-HANDOFF.md`。
