# MMD（Music Driver M.M.D.）

KAJA（梶原正裕）的 PC-98 **MIDI** 驱动——和 PMD（FM）同一作者、同一套设计思路。

| | |
|---|---|
| 覆盖 | **94 部作品 / 23 家会社** |
| 构建 | 至少 **6 个**（按内容哈希，见下） |
| 数据 | `.MMD` |
| 手法 | **静态解析**（驱动仿真卡在中断探测，见下） |

## 构建比想象的多

按文件名以为只有 3 个（2.2c / 2.2d / 2.2f），但**按内容哈希去重后至少 6 个**：

```
6592 B (8 部)   7128 B (6 部)   7057 B (5 部)
7071 B (3 部)   7081 B (3 部)   6218 B (2 部)
```

**同版本号、不同内容**——所以「一个解析器通吃 94 部」的假设只对简单的那批成立。
详见 [docs/DRIVER-INVENTORY.md](../../docs/DRIVER-INVENTORY.md)。

## 为什么这个不做仿真

MMD 安装时需要**带中断的 MIDI 板**：复位（`0xFF`）→ 收到 `0xFE` → 厂商命令 `0x94` →
然后逐个数中断号（INT2/INT1/INT0/INT5）探测，全失败就报
「MIDIボードが見つかりません」并退出。

把中断也模拟出来是可行的，但比 MMDR 的纯轮询复杂一档。
而 `.MMD` 的格式**已经被人文档化并验证过**，静态解析的成本低得多。

## 覆盖的格式

`docs/MMD.md` 里有完整规范：文件头（bpm / 移调 / 16 条轨道 / 曲名）、
位掩码命令、音符、变速、循环，以及和参考实现的两处差异。

## 用法

```bash
python src/mmd_parser.py song.MMD
```

## 验证状态

用 `eime_98`（エイミーと呼ばないでっ）的 35 首跑过：全部转换成功，
合计 31,266 音符 / 44.7 分钟，输出都能被标准 MIDI 库读取。

**听觉验证还没做。**

