# MMD（Music Driver M.M.D.）

KAJA（梶原正裕）的 PC-98 **MIDI** 驱动——和 PMD（FM）同一作者、同一套设计思路。

| | |
|---|---|
| 覆盖 | **36 部 / 756 首**（40 个包，全库 94 部共享此驱动） |
| 构建 | **14 个**（按内容哈希，见 [docs/BUILDS.md](docs/BUILDS.md)） |
| 数据 | `.MMD`（也有借 `.MDG` / `.MDL` / `.M` / `.LSP` 等扩展名的） |
| 手法 | **静态解析**（驱动仿真卡在中断探测，见下） |
| 归档 | `build/mmd_archive/GAL|非GAL/<作品名>/`（不进仓库） |

## 构建比想象的多

按文件名以为只有 3 个（2.2c / 2.2d / 2.2f），但**按内容哈希去重后有 14 个**，
大小从 4292 到 7128 字节不等，最大的一个被 8 个包共用。
完整对照表和命令语义见 **[docs/BUILDS.md](docs/BUILDS.md)**。

**同版本号、不同内容**——所以“一个解析器通吃 94 部”的假设只对简单的那批成立。

## 为什么这个不做仿真

MMD 安装时需要**带中断的 MIDI 板**：复位（`0xFF`）→ 收到 `0xFE` → 厂商命令 `0x94` →
然后逐个数中断号（INT2/INT1/INT0/INT5）探测，全失败就报
「MIDIボードが見つかりません」并退出。

不过驱动本身的 MIDI 出口是 `0xE0D0`（数据）/ `0xE0D2`（命令），和 MDRV98 一样，
理论上可以复用那套板子模型；只是还要先解出它的入口和定时器协议。

## 用法

```bash
cd src
python mmd_parser.py song.MMD
```

## 验证状态

- 40 个包、751 个 `.MMD` → **756 首**归档，全部可被标准 MIDI 库读取；
- 零首缺音色事件（program change）；
- 与 HOOT 实听对照：**基本一致**。`うきうきアイランド` 曾经的听感差异已确认
  来自**音源**——两边切到完全相同的 SF2 / VST 后表现几乎一致，2026-11-22 结档
  （见 [docs/BUILDS.md](docs/BUILDS.md)「已结档」）。

## ⚠️ 未解明

**不同构建之间仍有一些没完全搞清的怪癖**，这个解析器是“逐条对着反汇编修”出来的，
不是 100% 规格实现。已知差异点：

- 音符时值可能差 1 tick（驱动里计数器从 `length+1` 开始）；
- `0xE7` 的 16 位速度值（`buf[3]`）语义未确认；
- `0xE6`（切 MIDI 通道）未实现；
- `0xDD`/`0xDF` 存的参数如何组合进 `0xDE` 的 SysEx 未确认。

以上都**没有证据表明影响现有 756 首的产出**，暂不追；`うきうきアイランド`
按“可能存在未知怪癖”结档。

## 音源说明（重要）

**部分作品是按 Roland SC-55 / SC-88（GS）硬件写的，不是纯 GM。**

由此带来两个问题：

1. **音色**：GS 的变体音色靠 bank select（CC0/CC32）选择。我们的导出目前只发
   program change、**没有输出 bank**，所以在纯 GM 音源上同一 program 号可能是
   完全不同的音色。用支持 GS 的音源（SC-VA、SC-88 SoundFont 等）渲染才对得上。
2. **SysEx**：数据里嵌的 SysEx（`0x98`，多为 GS reset / EFX 参数）是**当年硬件专用**
   的老消息。现代软音源遇到它们可能直接忽略，也可能错误响应，导致音色、音量、
   效果异常——“放到现在听起来有怪声”很多时候是这个原因，不是文件坏了。

实听对照也印证了这一点：`うきうきアイランド` 在 HOOT 和我们导出**用同一个
SF2/VST 渲染时几乎无差别**——差异来自合成器，不来自解析。
