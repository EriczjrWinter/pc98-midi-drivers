## 命令语义（按 `930f0816a7` / `8b0da59644` 反汇编确认）

字节 < 0x80 = 音符；0x80–0x8F = 位掩码形式；其余按跳表（`0x666` / `0x67C`，64 项）分派：

| 命令 | 行为 |
|---|---|
| `0x90–0x97` | 发预置 SysEx（GS reset / GM on 等） |
| `0x98` | 内嵌 SysEx：读到 `F7`，`0x80–0x82` 是占位符，`0x83` 清校验、`0x84` 发校验 |
| `0x99–0xBF` | 空操作 |
| `0xC0–0xCD` | 预置 SysEx（带参数） |
| `0xD8–0xDB` | 空操作 |
| `0xDC` | 发 GS 消息（带轨道参数） |
| `0xDD` / `0xDF` | 存参数到轨道缓冲（供 `0xDE` 用） |
| `0xDE` | 用存下的参数发 GS 消息 |
| `0xE2` | 选音色：CC0（音色库）+ **PC（buf[2]）** —— 驱动里 0xE2 处理函数直接落入 0xEC |
| `0xE6` | 切换 MIDI 通道：`ch = (buf[2]-1) & 0x0F` |
| `0xE7` | 变速（写定时器端口 0xE1/0xE2） |
| `0xE8` / `0xE9` / `0xEF` | 空操作 |
| `0xEA` | **通道触后**（`0xD0|ch` + 1 字节） |
| `0xEB` | 控制变更（`0xB0|ch`，CC 号 = buf[2]，值 = buf[3]） |
| `0xEC` | 音色（`0xC0|ch`，程序号 = buf[2]） |
| `0xED` | **复音触后**（`0xA0|ch` + 2 字节） |
| `0xEE` | 弯音轮（`0xE0|ch` + 2 字节） |
| `0xF8` / `0xF9` | 循环结束 / 开始 |
| `0xFD` | 无条件跳转 |
| `0xFE` | 结束 |

**踩过的坑**：`0xEA` 和 `0xED` 一度被写反（触后类型互换），`0xD8–0xDF` 曾被当成
MIDI 消息（其实是 SysEx 参数，会产生假弯音——`ukiukiis`/`akasui` 的“音色怪异”就是它），
`0xE8/0xE9/0xEF` 曾被当成消息（会产生非法状态字节）。

## 未解明（至少这些）

这张表是从反汇编里逐条抠出来的，**不是官方规格**。以下差异点尚未 100% 确认：

1. **音符时值差 1 tick**：驱动里音符计数器从 `length+1` 开始（`0x5D0`），我们按
   `length` 算 gate，所以每个音略短 1 tick（十几毫秒）。
2. **`0xE7` 的 16 位速度**：驱动往 MIDI 板写 `0xE2`=buf[3]、`0xE1`=buf[2]，
   我们只按 buf[2] 用拟合公式换算，`buf[3] != 0` 的情况没验证过。
3. **`0xE6` 通道切换**：`ch = (buf[2]-1) & 0x0F`，没实现；已知曲目里没用到。
4. **`0xDE` 的 SysEx 组装**：`0xDD`/`0xDF` 存进轨道缓冲的参数如何拼进消息，未验证。
5. ~~**`うきうきアイランド`（`930f0816a7` 构建）与 HOOT 播放仍有可听差异**，
   原因待查~~ —— **已结档，见下节**。
6. **循环**：`0xF9`/`0xF8` 的嵌套与计数只按“最多走一遍”处理，没有完全对齐驱动的
   循环栈语义。

## 已结档：`うきうきアイランド`（2026-11-22）

`930f0816a7` 构建。与 HOOT 的听感差异**确认来自音源**：把两边切到完全相同的
SF2 / VST 后，表现几乎一致。所以不是数据用法 bug，解析器不改，按“可能存在未知怪癖”
结档。同构建的 `赤い水晶の瞳` 一直正常，也印证了构建本身没问题。

当初怀疑的四条（音符 +1 tick / `0xE7` 16 位速度 / 循环语义 / `0xE6` 通道切换）
**一条都没采用**，留作以后同构建再出问题时的排查顺序。
