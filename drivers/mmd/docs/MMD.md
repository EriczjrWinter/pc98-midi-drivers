## 覆盖范围

HOOT 全库统计：**94 部作品，23 家会社**，
是所有 PC-98 私有 MIDI 驱动里复用度最高的（第二名 `DOFMDX98` 79 部）。

会社例：13cm、4x9、active、ail、apricot、himeya、discovery、gainax、fairydust……

## 两个已知构建

| 版本 | 大小 | 入口 |
|---|---|---|
| 2.2c | 6592 B | `jmp 0x1359` |
| 2.2d | 7071 B | `jmp 0x141C` |
| 2.2f | 7057 B | `jmp 0x1406` |

`/In` 是「找到 MIDI 板后用哪个中断」，**不是**跳过板子探测。

## 驱动仿真：卡住了

MMD 需要**带中断的 MIDI 板**。安装时的探测流程（实测 I/O 序列）：

```
读 0xE0D0 / 0xE0D2
写 0xFF 到 0xE0D2（MPU 复位）
读状态 bit6 → 数据口读 0xFE（ACK）
写 0x94 到 0xE0D2（厂商命令）
轮询状态与数据口……
随后逐个数中断号探测：INT2 / INT1 / INT0 / INT5
全失败 → 「MIDIボードが見つかりません」→ 退出
```

只做 MPU 复位应答还不够，它会继续要求板子产生**中断**。
把中断也模拟出来是可行的，但比 MMDR 的纯轮询复杂一档。

**所以本驱动改走静态解析。**

## `.MMD` 格式

格式来源：Devin Acker 2015 年的 [MMD → MIDI 转换器](https://gist.github.com/devinacker/bdc58cfdba6a1ee80449)（WTFPL），
本文档在其基础上按实测补充了两处（见「与原版的差异」）。

### 文件头

```
+0x00  u8    bpm
+0x01  u8    transpose（有符号；超出 ±36 视为 0）
+0x02  16 × (u16 轨道偏移, u8 key, u8 channel)     ch == 255 表示空轨
+0x50  曲名（Shift-JIS，NUL 结尾）
```

`key` 是每轨的移调（有符号，>64 视为负数）。

### 轨道数据

循环读一个 `cmd` 字节：

**位掩码形式**（`(cmd & 0xF0) == 0x80`）：

| bit | 含义 |
|---|---|
| `0x08` | `buf[0]` 存在 |
| `0x04` | `buf[1]` 存在 |
| `0x02` | `buf[2]` 存在 |
| `0x01` | `buf[3]` 存在 |

未出现的字节**沿用上一次的值**（运行状态）。所以 `0x80` 表示「四个字节全部省略」。

**普通形式**：`buf[0] = cmd`，随后读 `buf[1] buf[2] buf[3]`。

### 命令

| `buf[0]` | 含义 |
|---|---|
| `< 0x80` | **音符**：`note, delay, length, velocity` |
| `0xFE` | **结束** |
| `0xE7` | **变速**：`buf[2]`=tempo 值，`buf[3]`=渐变量 |
| `0xF9` | **循环开始** |
| `0xF8` | **循环结束**：`buf[1]`=次数（0 = 无限） |
| `0xD8–0xDF` / `0xE8–0xEF` | **其它 MIDI 消息**：类型 = `buf[0] & 0x0F`，数据 `buf[2] buf[3]`（`0xC`/`0xD` 只需一个字节） |

变速公式（与参考实现一致）：

```
tempo_us = 64 × 60,000,000 / (bpm × buf[2])
```

### 与原版（Devin Acker 2015）的差异

以下每一条都是**拿实机录音对照后**才发现的：

1. **`c0 == 0` 是休止，不是音符。**
   掩码命令（`0x80–0x87`）的 bit3 未置位时 `buf[0]` 保持上一次的值；
   而在一条轨道的最开头，`buf[0]` 的初值是 0，于是原版会把它当成「音符 0」发出去。
   实测这会让鼓轨（ch8）多出一倍音符——真实数据里第一个命令常是 `84 10`（只设 delay）。

2. **`buf[1]` 是「本命令之后」的等待。**
   原版逻辑是对的，但如果误写成「之前」，每个音符都会被自己的 delay 提前，
   节奏整体错位——而且听感只是「有点赶」，不容易察觉。

3. **补 `0xD8–0xDF` 一族。**
   原版的判据 `(buf[0] & 0xF8) == 0xE8` 只覆盖 `0xE8–0xEF`；
   实测数据里大量出现 `0xDD`（通道触后）和 `0xDE`（弯音）。

4. **`kind == 0xF` 跳过**（`0xDF`/`0xEF` 不是通道消息），否则会写出非法的 `0xF0` 状态字节。

5. **无限循环再多走一遍**（让结尾完整；驱动本来会一直重复，录音只是按 CD 长度截断）。

6. **同音连打改成「延长已有音符」**（与参考实现一致）。原版用 `0xA0` 触后当占位，
   这里直接把挂起音符的结束时间往后推——效果相同且不产生多余事件。
   实测这一条把「多出的音符」从 54 个降到 4 个。

7. 曲名按 Shift-JIS 解（原版按 ASCII）。

## 验证

用 `eime_98` 的 35 首试跑，全部转换成功、输出都能被标准 MIDI 库读取。

### 与实机录音对照

参考文件：`Amy's Fantasies (1996)\PC98Track 01_GS.mid`（HOOT 实机录制，282.6 秒 / 4758 音）。
对应 `EMI_01.MMD`（主題歌）。

| 范围 | 参考 | 我们 | 匹配 | 召回 |
|---|---|---|---|---|
| 前 200 秒 | 3755 音 | 3757 音 | 3753 | **99.95%** |
| 全曲 | 4758 音 | 4748 音 | 4419 | 92.88% |

- **每个通道的 program 集合完全一致**（如 ch1 `[8,11,15,53,80,82,94]`）
- 前 200 秒只漏 2 个音、只多 4 个音
- 音符时间误差在 **50 毫秒**内

**全曲召回率掉到 92.88% 的原因**：存在约 **0.3–0.5% 的累积漂移**
（到 226 秒时快 73 毫秒），超过 60 毫秒的容差后就判定不上了。
尾部逐音对照其实是 42 对 42、完全一致，只是整体偏早。

漂移来源推测在 tempo 的计算/取整，尚未定位。**听感上可忽略，但确实存在。**

**人工试听（主观）已通过**（2026-11-27）；不是全部 756 首逐一确认，音色与力度仍建议抽检。

## 其它作品上的表现（TH02）

用 `tohofuma_98`（東方封魔録，15 首）对照官方 MIDI（ZUN 自己发布的）：

| 曲 | 我们 | 官方 | 结论 |
|---|---|---|---|
| BOSS1 She's in a temper!! | 1373 音 / 50.6 秒 | 1453 / 56.9 | 接近（差 5%） |
| OP 東方封魔録 | 2380 / 83.5 | 2492 / 90.0 | 接近（差 8%） |
| STAGE1 End of Daylight | 1868 / 116.1 | 1899 / 130.0 | 接近（差 11%） |
| **STAGE4 幽幻乱舞** | 3227 / **513 秒** | 1665 / 74.1 | **爆炸** |
| **MIMA Complete Darkness** | 28051 / **757 秒** | 3745 / 139 | **爆炸** |

### 爆炸的原因

STAGE4 只有 2 KB，却含**嵌套最多 7 层、次数最高 15**的循环。嵌套次数相乘就把时长放大到 7 倍。

三种处理都试过，没有一种全对：

| 方式 | BOSS1 | STAGE4 |
|---|---|---|
| 用次数（当前默认） | 50.6 秒 ✓ | 513 秒 ✗ |
| 忽略次数 | 44.4 秒 ✗ | 39.9 秒 ✗ |
| 官方真实值 | 56.9 秒 | 74.1 秒 |

**结论（2026-11-24 更新）：`F8` 的深层嵌套语义已由 FMD 侧实测确认。**
轨道项里是 **6 字节/层的循环栈**（深度 `[bx+0x2B]`）：`0xF9` 压栈、`0xF8` 结束
（次数在 `AH`，减到 0 弹层，`0` = 无限）、`0xFD`/`0xFC` 是定位/跳转。
MMD 解析器此前按“最多走一遍”处理，深层嵌套的时长偏差（STAGE4 513 s vs 官方 74.1 s）
就是这个原因。

> 注意：**FMD 的 `0xFD` 是同步标记，与 MMD 的跳转语义不同**——两边的 `0xFD` 不要互套（FMD 侧实测见 `FMD-BUILDS.md` §34.9）。

### 另一处缺口（已解）

`ukiukiis_98`（うきうきアイランド）里出现 **413 次「未知命令 E2」**，
Devin 的文档也没覆盖。**现在已从驱动反推确认**：`0xE2` 是“每轨一个音色号”，
驱动里的处理函数直接落入 `0xEC`，即向 `0xC0|ch` 发 program change（见
[BUILDS.md](BUILDS.md)）。

## 不同作品的特征差异

用 `tools/mmd_features.py` 扫三个包，差异非常明显：

| 特征 | eime_98 ✅ | tohofuma_98 ⚠ | ukiukiis_98 ⚠ |
|---|---|---|---|
| 文件数 / 有效轨 | 35 / 370 | 15 / 234 | 27 / 197 |
| 最大循环嵌套 | **2** | **4** | 2 |
| 循环标记不配对 | 2 | **56** | 1 |
| 循环次数范围 | 0 / 2 / 6 | 0 ~ 42 | 0 ~ 8 |
| MIDI 消息类型 | B0 C0 D0 **E0** | 只有 B0 C0 | B0 C0 D0 E0 |
| 变速（含渐变） | 126（0） | 59（**6**） | 40（0） |
| 未知命令 | DF×33 | 90×2 F7×2 | **E2×288** DF×31 90×27 |

**关键关联**：eime_98 是唯一通过实机验证的（99.95%），它的循环嵌套只有 2 层、
不配对 2 处；而 TH02 嵌套 4 层、不配对 56 处——正好是它时长放大的根源。

### 可转换性判定

`mmd_features.py` 会顺带给出判定，阈值按实测调过：

```
eime_98       ✅ 可放心转换
tohofuma_98   ⚠ 循环嵌套 4 层；循环标记不配对 56 处；tempo 渐变 6 处
ukiukiis_98   ⚠ 未知命令 346 个（DF, 90, E2）
```

判定规则：

| 条件 | 含义 |
|---|---|
| 未知命令 > 100 个或占比 > 1% | 有参数会被丢掉 |
| 最大循环嵌套 > 2 层 | 时长可能被放大 |
| 循环标记不配对 > 5 处 | 段落长度可能不准 |
| 有 tempo 渐变 | 未支持 |
