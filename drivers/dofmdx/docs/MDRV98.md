# MDRV98 / DOFMDX98（D.O. 的 MIDI 驱动）

覆盖 **79 部作品**（do / foster / zyx 三家），是本地样本第三多的驱动。
数据是 `.FMD`（签名 `68V2`，明文）。

## 装载模型（已修正）

包里有三个文件：

| 文件 | 大小 | 角色 |
|---|---|---|
| `DOFMD_98.BIN` | **206** 字节 | 装载桩（**不要和 MDRV98 拼在一起**） |
| `MDRV98` | **11519** 字节 | 真正的驱动，**单独装载在偏移 0** |
| `CRxxx?.FMD` | — | 音乐数据（`F`=OPN / `C`=MT-32 / `G`=GS） |

### 踩过的坑：装载位置

第一版把 `MDRV98` 接在 BIN 后面（偏移 0xCE），因为 206 = 0xCE 看着很合理。

**错了。** 后果是驱动里的 `mov si, 0x29`（跳转表）读到了 **BIN 的字节**
（`39 00 8c 0e`），于是 `call ax` 跳到了 `0x0E8C` 的延时循环。

**MDRV98 必须单独装在偏移 0**，这样跳转表项
`0x0041` / `0x022B` / `0x0197` 才落在它自己的范围内。

验证：修正后功能 0 的硬件检测成功，端口基址算出 `0x0188`（PC-98 声卡标准口）。

### 两个文件用的是不同的端口

| 文件 | 端口 |
|---|---|
| `DOFMD_98.BIN` | `0x7D0` / `0x7E0` / `0x7E8` |
| `MDRV98` | `0x188` / `0x18A`（标准声卡） |

所以那个 206 字节的 BIN 很可能是**另一块 MIDI 接口板**的装载器，
MDRV98 自己才是 0x188 声卡的驱动。

## API 派发（完整）

```asm
pusha ; push ds ; push es
cmp ah, 0Ch
jae 退出
mov si, 0x29          ; 跳转表 A
or al, al
je  +3
mov si, 0x17D4        ; 跳转表 B（AL != 0）
xor al, al
xchg al, ah           ; AX = 功能号
add ax, ax
add si, ax
mov ax, cs ; mov ds, ax ; mov es, ax
lodsw                 ; ax = 表[功能号]
pop si
call ax
...
iret                  ; ← 以 iret 结尾，必须按中断方式调用
```

**两张表由 `AL` 选择**，`AH` 是功能号（0–11）。

### 跳转表 A（`0x0029`）

| 功能 | 入口 | 作用 |
|---|---|---|
| 0 | `0x0041` | **硬件检测**（读 `in 0x60` / `in 0xA460`，探测声卡） |
| 1 | `0x022B` | **打开曲子**（`BX`=数据段, `DX`=偏移） |
| 2 | `0x0197` | 初始化 4 个通道结构（`0x1262` 起，每个 0x40 字节） |
| 3 | `0x0430` | **开始播放**（`[0x1204]=[0x1205]=1`） |
| 4 | `0x0439` | **停止播放**（`[0x1204]=[0x1205]=0`） |
| 5 | `0x0442` | 查询状态 |
| 6 | `0x02DD` | |
| 7 | `0x046B` | |
| 8 | `0x049B` | |
| 9 | `0x0124` | |
| 10 | `0x04A1` | |
| 11 | `0x018E` | |

## 打开曲子的参数（重要）

```asm
022B: test byte [0x1200], 0xFF
      ...
0239: mov [0x120A], bx      ; 存数据段
      mov [0x120E], bx
      mov es, bx              ; ← BX 是【段】
      mov di, dx              ; ← DX 是【偏移】
      mov [0x1210], dx
      mov ax, es:[di]         ; 读偏移表第一项
      add ax, di              ; 加上基址
      mov [0x1216], ax        ; 指针 1
      mov ax, es:[di+2]
      add ax, di
      mov [0x121A], ax        ; 指针 2
      mov ax, es:[di+4]
      add ax, di
      mov [0x1212], ax        ; 指针 3
```

两个坑：

1. **`BX` 是段，不是 0**。第一版传 `BX=0`，于是 `mov es,0` 读到了中断向量表。
2. **`DX` 要跳过 `68V2` 魔数**。传 `DX=0` 时读到 `0x3836`（就是 "68V2" 的字面值），
   传 `DX=4` 后指针变成 `0x00C3` = 4 + 表[0]，正确。

修正后实测：

```
[0x120A] = 4000    ← 数据段
[0x1210] = 0004    ← 偏移
[0x1216] = 00C3    ← 指针解析正确
```

## 端口

| 端口 | 方向 | 用途 |
|---|---|---|
| `0x188` / `0x18A` | out/in | 声卡寄存器与数据（**MDRV98 用这个**） |
| `0x7D0` / `0x7D2` | out | 数据（BIN 用） |
| `0x7E0` / `0x7E2` | in | 状态（BIN 用） |
| `0x7E8` | out | 控制（BIN 用） |

**仿真里 `in` 必须回读上次 `out` 的值**——驱动的硬件检测是靠
"写 `0xBF` 再读回来比对" 来判断声卡存在与否的。返回常数会直接判失败。

## `AL` 是板卡选择器（关键发现）

```asm
mov si, 0x29
or  al, al
je  +3
mov si, 0x17D4      ; ← AL != 0 换另一张表
```

**同一个 AH 功能号，`AL` 不同走不同的表：**

| AL | 表 | 用途 |
|---|---|---|
| `0` | `0x0029` | 通用 / FM |
| `≠0` | `0x17D4` | **MIDI** |

这解释了为什么之前一直只写 `0x188`（FM）——**我们一直用 AL=0**。

### 跳转表 B（`0x17D4`，MIDI 用）

| 功能 | 入口 | 作用 |
|---|---|---|
| 0 | `0x17FE` | **MIDI 板探测**（`call 0x18A2`） |
| 1 | `0x1807` | **MIDI 初始化 + 数据**（`ES:DI`） |
| 2 | `0x1829` | 设置 |
| 3 | `0x183C` | `[0x218F] = 0` |
| 4 | `0x1842` | `[0x218F] = 1` |
| 5 | `0x1848` | 状态查询 |
| 6 / 10 | `0x17EA` | 空（`ret`） |
| 7 | `0x186F` | |
| 8 | `0x187F` | |
| 9 | `0x1895` | |

### MIDI 探测的条件

```asm
18A2  mov dx, 0xE0D2
18A5  in  al, dx
18A6  cwde
18A7  cmp ax, 0xFFFF
18AA  je  0x18BE        ; 读到 0xFF → 直接存
      ... 一系列初始化 ...
18BC  xor ax, ax
18BE  mov [0x18C2], al  ; MIDI 板标志
```

**只有 `in 0xE0D2` 返回 `0xFF` 才会把 `[0x18C2]` 置为非零**，否则清零。
实测让端口返回 `0xFF` 后，标志变成 `0xFF`，MIDI 通路被打开。

## MIDI 输出例程（`0x2109`）

```asm
2109  mov dx, 0xE0D2      ; ← 注意是 0xE0D2，不是 0xE0D0
210C  mov cx, 0xFFFF
210F  xor bx, bx
2111  in  al, dx
2112  test al, 0x40
2114  je  0x211D          ; bit6 清零 = 就绪
2116  loop 0x2111
2118  bx = 0xFFFF         ; 超时
211D  mov al, ah
211F  out dx, al          ; 写数据
2120  call 0x214B         ; 等 ACK
212A  cmp al, 0xFE        ; 收到 0xFE 算成功
```

**数据口是 `0xE0D2`，不是常见的 `0xE0D0`。** 仿真里两个都要当数据口收。

## 仿真器现状

`src/mdrv_emu.py`：

```
装载      ✅ MDRV98 单独在偏移 0
硬件检测  ✅ 端口基址 0x0188
MIDI 探测  ✅ [0x18C2] 能置上
MIDI 输出  ✅ 例程已定位（0x2109，写 0xE0D2）
打开曲子  ✅ 参数与指针都对
出音      ❌ 还没跑通
```

### 还差什么

播放靠什么**周期性推进**仍未确定。

试过的组合（AL=0/1 × AH=1/2/3/6/8/9/10/11 × 不同初始化顺序）都没有音符输出。

已知的约束：

- MDRV98 **没有任何 `INT 21h`、也不写 IVT**——它是纯可调用库
- 表 B 的功能 6/10 是空 `ret`
- `[0x1204]`（播放标志）在 `0xAD7` 被读，但那段反汇编不出代码

下一步方向：

1. 找 `0xAD7` 所在函数的真正入口（向前找 `ret` 边界）
2. 追 `[0x218F]`（表 B 功能 3/4 的开关）被谁读
3. 直接跑 HOOT 抓它的调用序列（最可靠）

## 数据格式

`68V2` + 4 字节一组偏移表 + 紧凑命令流。
之前分析过：note-like 字节 `a4`/`a2 0c` 成对出现，还有 `e0`/`e1` 命令。
**如果仿真跑通，就不需要静态解了。**
