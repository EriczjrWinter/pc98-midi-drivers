# MDRV98 / DOFMDX98（D.O. 的 MIDI 驱动）

覆盖 **79 部作品**（do / foster / zyx 三家），是本地样本第三多的驱动。
数据是 `.FMD`（签名 `68V2`，明文）。

## 装载模型（已确认）

包里有三个文件：

| 文件 | 大小 | 角色 |
|---|---|---|
| `DOFMD_98.BIN` | **206** 字节 | 装载桩，入口就是偏移 0 |
| `MDRV98` | **11519** 字节 | 真正的驱动，接在 BIN 后面 |
| `CRxxx?.FMD` | — | 音乐数据（`F`=OPN / `C`=MT-32 / `G`=GS） |

**206 = 0xCE**，正好是 MDRV98 的起始偏移。所以内存布局是：

```
CS:0000   DOFMD_98.BIN   206 字节
CS:00CE   MDRV98         11519 字节
SP = 0x4CE
```

装载桩做的事：

```asm
cli
mov dx, 0x7E8 ; out 0x80      ; 声卡控制口
mov ss, cs ; mov sp, 0x4CE
mov [0x114], 0 ; [0x116], 0xFA ; int 0x45   ; PC-98 BIOS
int 0x14                      ; 串口
mov [0x1FC], 0x39 ; [0x1FE], cs   ; IVT[0x7F] = CS:0x0039
mov dx, 0x7E8 ; out 0x81
sti ; hlt ; jmp $
```

**`[0x1FC]` 就是 IVT 的 INT 7Fh 表项**（0x1FC / 4 = 0x7F）。
实测仿真里安装后向量确实是 `2000:0039`，和代码一致。

## 两个入口

| 入口 | 位置 | 作用 |
|---|---|---|
| **INT 7Fh** | `CS:0x0039` | **硬件中断处理**，读 `0x7E0` 判断中断源 |
| **API** | `CS:0x00CE` | 功能调用，`cmp ah, 0Ch` |

**别把两个搞混**——INT 7Fh 那个不是功能调用入口，它服务硬件中断。

## API 派发（已解）

```asm
pusha ; push ds ; push es
cmp ah, 0Ch
jae 退出
push si
mov si, 0x29          ; 跳转表 A
or al, al
je  +3
mov si, 0x17D4        ; 跳转表 B（AL != 0）
xor al, al
xchg al, ah           ; AX = 功能号
add ax, ax
add si, ax
mov ax, cs ; mov ds, ax ; mov es, ax
lodsw                 ; ax = 表[功能号]
pop si
call ax
```

**两张表由 `AL` 选择**：
- `AL == 0` → 表在 `0x0029`
- `AL != 0` → 表在 `0x17D4`

功能号 0–11（AH），表 A 的内容：

| 功能 | 处理函数 | 备注 |
|---|---|---|
| 0 | `0x0041` | **硬件检测**（读 `in al,0x60` 和 `0xA460`） |
| 1 | `0x022B` | |
| 2 | `0x0197` | 初始化通道结构（`si=0x1262`，每 0x40 字节一个，4 个） |
| 3 | `0x0430` | |
| 4 | `0x0439` | |
| 5 | `0x0442` | |
| 6 | `0x04DD` | |

## 端口

| 端口 | 方向 | 用途 |
|---|---|---|
| `0x7D0` / `0x7D2` | out | 数据 |
| `0x7E0` / `0x7E2` | in | 状态（**中断源标识，0 或 1**） |
| `0x7E8` | out | 控制（0x80 初始化 / 0x81 启动） |

## 仿真器现状

`src/mdrv_emu.py`：

```
装载     ✅ BIN + MDRV98 拼接，段 0x2000
执行     ✅ 跑到 hlt
安装     ✅ INT 7Fh → 2000:0039（和代码一致）
API      ✅ 入口 CS:0x00CE，派发已解
MIDI     ❌ 还没出字节
```

### 卡在哪

调用 API（AH=0..12）之后**没有任何 MIDI 输出**。

两个可能：

1. **参数不对**：功能 0 是硬件检测（读 0x60 / 0xA460），
   我们的仿真里那两个端口返回 0，检测可能失败，导致后续功能不工作。
2. **数据没喂进去**：API 用的是驱动段内固定地址（`0x1200`、`0x1262`），
   不是外部传的指针——**数据可能要按特定方式拷进去**，还没找到入口。

### 下一步

1. 让 `in al,0x60` 和 `in al,0xA460` 返回合理值，看功能 0 能不能过
2. 反汇编功能 1（`0x022B`）——它长度可观，可能是"打开曲子"
3. 找 `0x1200` 那个标志的写入点

## 数据格式

`68V2` + 4 字节一组偏移表 + 紧凑命令流。
之前分析过：note-like 字节 `a4`/`a2 0c` 成对出现，还有 `e0`/`e1` 命令。
**如果仿真跑通，就不需要静态解了。**
